# Лендинг Personal CRM

Одна статичная страница: рассказывает о приложении и ведёт в него кнопкой «Открыть приложение».
Сделана на Astro и Tailwind CSS 4 по макету из папки `design/`.

## Запустить у себя

Нужны Node.js 22.12 или новее и pnpm.

```
pnpm install
pnpm dev
```

Страница откроется на http://localhost:4321. Правки в коде видны сразу.

Посмотреть готовую сборку — ровно то, что попадёт на сервер:

```
pnpm build
pnpm preview
```

Сборка складывается в папку `dist/`.

## Где что менять

- Адрес приложения, куда ведут кнопки, — `src/config.ts`.
- Цвета, шрифты, размеры, отступы, скругления — только в `src/styles/tokens.css`.
- Блоки страницы — `src/components/`, по одному файлу на блок.
- Иконки берутся прямо из `design/icons/`.

## Выкатка

Лендинг живёт на https://personalcrm.site. Какая версия сейчас на сайте — видно на https://personalcrm.site/version.txt: там SHA коммита.

### Как выкатить новую версию

1. Закоммитьте изменения и отправьте их в ветку `main`: `git push`.
2. Больше ничего делать не нужно. GitHub Actions (вкладка **Actions** в репозитории, workflow **Deploy**) сам соберёт сайт, зальёт его на сервер и проверит. Обычно это около минуты.
3. Проверьте: обновите https://personalcrm.site, а в https://personalcrm.site/version.txt должен быть SHA вашего коммита (его показывает команда `git rev-parse HEAD`).

### Что происходит при выкатке

1. GitHub собирает сайт командой `pnpm build` — получается папка `dist/`.
2. `deploy/deploy.sh` заливает `dist/` на сервер через `rsync --delete`: новые и изменённые файлы копируются, лишние удаляются, подмена происходит разом в конце. Сервер собирает только GitHub, на самом сервере ничего не собирается.
3. nginx отдаёт эту папку как сайт.
4. Проверка: главная должна ответить 200, а `version.txt` — показать SHA нового коммита. Иначе workflow станет красным и GitHub пришлёт письмо.

Стенда и отката нет: если что-то сломалось — исправьте и отправьте новую версию.

### Где что лежит

- `.github/workflows/deploy.yml` — запуск выкатки на каждый push в `main`.
- `deploy/deploy.sh` — заливка на сервер и проверка.
- На сервере — папка `/var/www/personalcrm/landing` пользователя `landing`. Ключ этого пользователя умеет только записывать файлы в эту папку: ни команд, ни чтения, ни других папок.
- GitHub → **Settings → Secrets and variables → Actions**: секрет `DEPLOY_SSH_KEY` (ключ, которым GitHub заливает сайт) и переменные `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_KNOWN_HOSTS`, `SITE_URL`.
